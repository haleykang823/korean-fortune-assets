# 운세 프로그램용 자료 · 에셋 모음

이름과 생년월일만 입력받아 운세를 보여주는 프로그램을 만들기 위한 데이터, 계산 로직, 외부 에셋 출처를 모았습니다.

---

## 폴더 구조

```
fortune-assets/
├── README.md                     이 문서
├── data/                         언어 중립 JSON (어떤 스택에서든 그대로 사용)
│   ├── zodiac-animals.json       십이지(띠) 12종 + 삼합/육합/충 궁합표
│   ├── heavenly-stems.json       천간 10간 + 월주/시주 산출 규칙
│   ├── five-elements.json        오행 상생·상극 + 색/방위/계절/숫자 상징
│   ├── western-zodiac.json       서양 12별자리 + 원소/지배행성/궁합
│   ├── numerology.json           생명수 1~9 + 마스터 수 11/22/33
│   ├── name-strokes.json         한글 자모 획수표 + 사격(四格) + 81수리 전체

│   ├── fortune-core.js           사주/띠/별자리/획수 계산 + 운세 조립 (의존성 0)
```

## 바로 써 보기

`data`, `src`, `demo`를 아무 정적 서버로 띄우고 `demo/index.html`을 열면 됩니다.
(ES 모듈이라 `file://`로는 안 열립니다. 반드시 http로 서빙하세요.)

```bash
npx serve fortune-assets
```

그다음 `http://localhost:3000/demo/index.html`.

코드에서 직접 쓸 때:

```js
import { loadFortuneData } from './src/load-data.js';
import { buildFortune } from './src/fortune-core.js';

const data = await loadFortuneData('./data');

const result = buildFortune({
  name: '김민수',
  birth: '1995-08-23',
  birthHour: null,        // 태어난 시를 모르면 null (시주를 뺍니다)
  // date: '2026-09-18',  // 생략하면 오늘
}, data);
```

`result`에는 화면에 바로 뿌릴 수 있는 형태로 전부 들어 있습니다.

```
result.summary.totalScore   64
result.summary.opening      "돼지띠 김민수님, 오늘의 기운을 펼쳐 보았습니다."
result.categories[]         총운/애정/금전/건강/직업학업/대인 — 각각 점수·등급·문구
result.lucky                색·숫자·방위·물건·음식·시간대
result.profile.zodiac       띠 정보 전체 (성격, 궁합 포함)
result.profile.westernSign  별자리
result.profile.lifePath     생명수
result.profile.saju         사주 네 기둥 + 일간 + 오행 분포
result.profile.nameFortune  사격(원격/형격/이격/정격)과 81수리 풀이
```

## 설계에서 꼭 지킨 것: 결과는 항상 같아야 합니다

`Math.random()`을 쓰면 새로고침할 때마다 운세가 바뀌어서 사용자가 바로 신뢰를 잃습니다.
그래서 `buildFortune()`은 **(이름 + 생년월일 + 조회 날짜)를 해시한 시드**로 결과를 만듭니다.

- 같은 사람이 같은 날 몇 번을 눌러도 결과가 동일합니다.
- 날짜가 바뀌면 자연스럽게 새 운세가 나옵니다.
- 서버도 DB도 필요 없습니다. 전부 클라이언트에서 계산됩니다.

주간/월간 운세를 넣고 싶으면 시드의 날짜 부분만 `2026-W38`이나 `2026-09`로 바꾸면 됩니다.

## 정확도에 대해 — 반드시 읽어 주세요

`fortune-core.js`의 사주 계산은 이렇게 검증했습니다.

| 항목 | 검증 |
|---|---|
| 일주 공식 | 2000-01-01 → **무오일** (알려진 값과 일치) |
| 연주·월주 | 1995-08-23 → **을해년 갑신월** (수기 계산과 일치) |
| 일주 | 1995-08-23 → **병술일** |
| 띠·별자리·생명수 | 1995-08-23 → 돼지띠 / 처녀자리 / 생명수 1 |

**다만 한 가지 한계가 있습니다.** 월주는 24절기의 절입 *시각*으로 갈리는데,
지금은 고정 근사일(입춘 2/4, 경칩 3/6 …)을 쓰고 있습니다.
따라서 **절입일 전후 하루에 태어난 사람은 월주가 틀릴 수 있습니다.**

정밀도가 필요하면 `getMonthBranchIndex()` **한 함수만** `lunar-javascript`로 교체하세요.
나머지 코드는 그대로 씁니다. (`assets/SOURCES.md` 5번 항목 참고)

그 외 알고 있어야 할 선택지들:

- **띠가 바뀌는 기준**: 입춘(기본값) / 음력 설날 / 양력 1월 1일 — 유파마다 다릅니다.
  `getZodiacAnimal(y, m, d, 'ipchun' | 'jan1')`로 바꿀 수 있습니다.
- **야자시**: 23시 이후 출생은 다음 날로 넘겨 일주를 잡도록 해 두었습니다(조자시/야자시 논쟁이 있는 부분).
- **진태양시**: 한국은 표준시가 동경 135도 기준이라 실제 태양시와 약 32분 차이가 납니다.
  `getFourPillars({ trueSolarTime: true })`로 보정할 수 있습니다.
- **성명학 획수**: 원래 한자 기준이고 유파(원획법/필획법/곡획법)마다 값이 다릅니다.
  여기 실린 표는 한글 자모 원획법이며, 한자 입력을 받지 않는 앱을 위한 실용안입니다.
- **복성(2글자 성)**: 남궁·황보·제갈 같은 성은 `COMPOUND_SURNAMES` 목록으로 자동 판별합니다.
  목록에 없는 성이 들어오면 `getSagyeok(name, table, su81, 2)`처럼 성의 글자 수를 직접 넘기세요.
  이름이 외자면(예: 김민) 원격·이격을 만들 수 없어 형격과 정격만 채워집니다.

## 만들면서 챙기면 좋은 것들

**흉한 결과를 어떻게 보여줄지 먼저 정하세요.**
데모를 돌려 보면 "이름(형격) 14수 이산격 · 흉 — 인연이 갈라지고 손실이 따른다" 같은 문구가 그대로 나옵니다.
사용자 이름을 두고 이런 말을 정면으로 띄우면 기분이 상합니다. 셋 중 하나를 고르세요.

1. 흉한 항목은 조언 형태로 바꿔 쓴다 (권장) — "이 부분은 관계에 공을 들이면 좋아집니다"
2. 점수만 보여주고 흉한 해설은 접어 둔다
3. 81수리 자체를 빼고 띠·별자리·오행만 쓴다

**개인정보는 최대한 안 받고, 받아도 안 보냅니다.**
이름과 생년월일은 그 자체로 개인정보입니다. 이 자료의 모든 계산은 클라이언트에서 끝나도록 만들었으니,
가능하면 서버로 보내지 말고 저장도 하지 마세요. 저장이 필요하면 `localStorage` 정도로 충분하고,
서버에 쌓는 순간 개인정보처리방침과 동의 절차가 필요해집니다.

**오락용 고지를 눈에 띄는 곳에 넣으세요.**
`buildFortune()` 결과에 `disclaimer` 필드를 넣어 뒀습니다.
앱스토어·구글플레이 심사에서도 운세 앱은 오락 목적임을 명시하는 편이 안전하고,
건강이나 재물에 대해 단정적인 예언을 하면 문제가 될 수 있습니다.

**문구는 계속 늘려야 합니다.**
지금 `fortune-templates.json`에는 카테고리당 4~5개씩 들어 있습니다.
같은 사용자가 며칠만 들어와도 문구가 반복되는 게 보입니다.
카테고리별 구간당 **15개 이상**으로 늘리는 게 좋고, 띠나 오행에 따라 다른 문구를 주면 훨씬 그럴듯해집니다.

## 데이터 출처와 라이선스

- `data/*.json`의 명리·민속 내용(십이지, 천간지지, 오행, 81수리 등)은 **전통적으로 공유되어 온 지식**을
  정리한 것입니다. 특정 저작물을 옮긴 것이 아닙니다.
- `fortune-templates.json`의 **모든 운세 문구는 이 프로젝트를 위해 새로 작성**했습니다.
  자유롭게 수정·사용하세요.
- 폰트·아이콘·이미지·라이브러리 등 외부 에셋은 `assets/SOURCES.md`에 라이선스와 함께 정리했습니다.
